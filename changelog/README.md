# История изменений (changelog)

Человекопонятная история обновлений Prereborn Companion и каждого плагина на русском языке.
Записи из этой папки — единственный источник для:

- раздела [prereborn.ru/changelog](https://prereborn.ru/changelog) и блока «Последнее обновление»
  на главной (сайт читает файлы этой ветки напрямую, без ручной публикации);
- текста GitHub Release для Companion (`windows-release.yml`) и для плагинов (`gh release create
  --notes-file`).

**Запись в changelog — обязательная часть каждого релиза** (major, minor и patch, включая мелкие
исправления). Релиз без записи о своей версии не считается завершённым, и автоматика его не
пропустит — см. «Проверки» ниже.

## Файлы

| Продукт | Файл |
|---|---|
| Companion | `changelog/companion.md` |
| Плагин с id `<id>` | `changelog/plugins/<id>.md` |

`<id>` — поле `id` из `plugins/<папка>/manifest.windows-live.json` (например, `dota2`, `pubg`).
Новый плагин настраивать не нужно: как только у него появляется `manifest.windows-live.json`,
CI требует файл `changelog/plugins/<id>.md` с записью о версии из манифеста, а сайт показывает
историю любого плагина из опубликованного каталога.

## Формат

```markdown
# Prereborn Companion

## 0.9.0 — 2026-10-21 — Короткое название обновления

Необязательный абзац: о чём обновление в целом.

### Новое
- Что появилось.

### Улучшения
- Что стало удобнее или лучше.

### Исправления
- Какие ошибки исправлены — как их видел пользователь.

### Что сделать после обновления
- Изменились ли настройки или нужны ли действия от пользователя.
```

- Первая строка файла — `# <название продукта>`.
- Заголовок версии: `## X.Y.Z — ГГГГ-ММ-ДД — Название`, разделитель — длинное тире с пробелами.
  Дата — день публикации релиза.
- Версии идут сверху вниз от новой к старой, каждая версия — один раз.
- Разделы только из списка выше, в любом составе; хотя бы один пункт в версии обязателен.
  Пустой раздел не пишите.

## Как писать

- По-русски и для обычного пользователя: что он заметит после обновления, а не что изменилось
  в коде.
- Только реальные изменения этого релиза. Ничего не придумывать и не обещать.
- Не вставлять сообщения коммитов, названия PR, номера тикетов (`WK-123`) и ссылки на PR.
- Технические подробности (SHA, прогоны CI, проверки) — в описании PR, не здесь.
- Историю старых релизов задним числом не дописывать по догадкам. Переносить можно только
  то, что подтверждается опубликованными release notes или описаниями слитых PR.

## Проверки

`node scripts/changelog.mjs` (без зависимостей):

- `check` — формат всех файлов и запись для текущей версии каждого
  `plugins/*/manifest.windows-live.json`. Запускается в CI на каждый PR.
- `check --companion X.Y.Z` / `check --plugin <id> X.Y.Z` — запись о конкретной версии.
  `windows-release.yml` выполняет это до сборки: тег `prereborn-vX.Y.Z` без записи падает,
  то же для `dota_candidate` / `pubg_candidate`.
- `notes companion X.Y.Z` / `notes plugin <id> X.Y.Z` — текст GitHub Release из записи. Без
  записи команда завершается ошибкой, поэтому плагин нельзя опубликовать по рецепту без неё.

Сайт показывает запись только после выхода версии: для Companion — когда она стала stable
`latest`, для плагина — когда версия появилась в опубликованном каталоге `catalog-v1`.
