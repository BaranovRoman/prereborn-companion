# 0.5.53 real GSI and overlay stabilization

## Scope

Correction pass after the first real-match test on 0.5.52. Source was inspected in the raw loopback GSI entry point, local detector/store, local overlay server, standalone renderer, Companion editor, and the old web Queue scene.

## Real-match root cause

The first broken transition was match creation itself. Normal Dota payloads include `map.customgamename: ""`. The TypeScript detector treated that empty string as false; the Rust parser converted it to `Some("")`, and the local detector interpreted any `Some` value as a custom lobby. It therefore returned before inserting `LocalMatch`.

A second production-shape bug existed at `in_progress -> post_game_pending`: `GsiSnapshot::is_in_match` required `player.activity == "playing"`, and `detector::handle_snapshot` required fresh `hero.id` plus `player.team_name` before it would inspect `POST_GAME`. Final Dota ticks can already say `activity: "menu"` and omit hero/team while `map.game_state` remains `DOTA_GAMERULES_STATE_POST_GAME`. Had tracking started, this would have persisted `interrupted` and still made finalization, rating arithmetic, W/L/history, SSE, and `match_finalized` outbox enqueue unreachable.

The parser also accepted only a string `map.matchid`; production-shaped numeric IDs are now normalized to the same string identity.

Finally, ranked/unranked bootstrap originally waited up to 60 seconds. Because mode is intentionally fixed when a match row is created, an early match could remain `Unknown` even after account sync succeeded and would finalize without an MMR delta. While the cache is unknown it now refreshes every two seconds; after bootstrap it returns to the normal 60-second cadence.

The correction treats POST_GAME as a lifecycle signal independent of activity and uses the already-persisted active match's team/identity. It does not create a match from a post-game-only startup and keeps mismatch/duplicate protections. Regression coverage drives the real `handle_gsi` entry point with numeric match ID, `activity: menu`, missing hero/team, and repeated final ticks, asserting one finalized row, +25 MMR, 1-0 tally, recent history, and one outbox event without a backend.

## Between Matches settings/data classification

| Old Queue capability | Classification | Companion behavior |
|---|---|---|
| Player profile / Steam avatar/name | Account data | Loaded through the authenticated companion account-settings response and cached locally. |
| Twitch channel avatar/name/live title/viewers | Account data | Loaded through the same authenticated response and cached locally. |
| Current MMR, session delta, W/L, last/recent matches | Local authoritative | Comes only from local-runtime SQLite/SSE. |
| Player/stream/featured/webcam/favorites/recent visibility | Meaningful locally | Same saved Queue settings; unsaved editor changes are posted live into the OBS renderer iframe and saved through the existing API. |
| Titles, channel goal, webcam URL, favorite hero IDs, recent limit, social links | Meaningful locally | Existing Queue settings contract retained. |
| Twitch chat message panel | Unavailable in local OBS contract | The ineffective editor checkbox was removed and the limitation is stated in the editor. Channel identity remains real account data. |
| Donation/subscriber/follower grids | Backend-event data, not in the local renderer contract | Not fabricated; social/community links remain when configured. |
| System status | Diagnostic/deprecated for broadcast composition | Not exposed as an editor control. |

The local finalized-match schema does not currently persist K/D/A or inventory. Those cells remain honest empty production slots; no values are synthesized from stale GSI. Adding durable match stats is a separate schema/lifecycle slice.

## Shared preview and OBS renderer

Both paths load `http://127.0.0.1:3666/overlay`. Editor-only messages mutate the same renderer component tree in-memory; save writes the same OverlayLayout/QueueSettings that the bare OBS URL fetches. Draft/gameplay widgets now expose direct drag bounds and resize handles; changes are posted back into DesignPage's real layout document. Minimap protection has direct drag/resize with the same saved `x/y/size` fields. Numeric controls remain available for precision.

## Observability

Transition logging now resolves the terminal row after it leaves the active query and records final state, result, detected rating delta, and rating-after. This makes a future real capture distinguish `finalized`, `interrupted`, and `needs_review` without raw-payload logging.
