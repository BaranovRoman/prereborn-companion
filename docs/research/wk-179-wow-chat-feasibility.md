# WK-179 — Twitch-чат в WoW Forever: техническое заключение

Дата: 2026-10-21. Статус: архитектура **не подтверждена**, прототип не выпускается в production.

## Вопрос

Можно ли доставлять сообщения Twitch из Companion в Lua-аддон WoW Forever 1.60.70374 в реальном
времени, используя только официально поддерживаемые механизмы клиента — без отправки клавиш,
инъекций, чтения памяти, модификации клиента и второго игрового аккаунта.

## Что такое WoW Forever для аддонов

- Это официальный клиент Blizzard (патч 1.60.1, Interface 16001; в TOC-суффиксах `Forever` —
  алиас `Camelot`). Действуют обычные правила Blizzard для аддонов и автоматизации.
- В Forever включены ограничения аддонов из Midnight («addon disarmament», secret values) —
  клиент стал строже, а не мягче.
- В заметках об изменениях API 1.60.1 нет новых сетевых, файловых или clipboard-механизмов,
  а также изменений SavedVariables. Из релевантного: trial-аккаунтам запрещено отправлять addon
  messages, `SendChatMessage("EMOTE")` вне инстансов требует аппаратного события.

## Входящие каналы, доступные Lua-аддону

| Механизм | Поддерживается официально | Real-time | Вывод |
|---|---|---|---|
| Сеть (WebSocket/HTTP/сокеты) | Нет такого API | — | Невозможно |
| Чтение произвольных файлов | Нет такого API | — | Невозможно |
| SavedVariables | Да | **Нет** — читаются только при входе или `/reload` | Только пакетная доставка с `/reload`; это не чат |
| Чат-каналы и addon messages | Да | Да, но только от **игровых** персонажей | Требует второго аккаунта/клиента-ретранслятора — исключено условием |
| Clipboard | Нет API чтения | — | Невозможно |
| Отправка клавиш (`/команда payload` в чат) | Автоматизация ввода | Да | Исключено условием (риск ToS, мешает игроку) |
| Изменение текстур на диске | Недокументированный трюк 2014 г., ~1 байт за раз | — | Не исследовался по условию: нет подтверждения для 1.60.1 |
| Пиксельный канал (LibSerpix и т.п.) | Да | Да | Работает только **из** игры наружу, не внутрь |

## Заключение

Безопасного real-time канала «внешнее приложение → Lua-аддон» в WoW Forever нет. Единственный
официальный входящий механизм — SavedVariables — читается клиентом только при входе в мир или
`/reload`, что не подходит для живого чата. Остальные варианты либо требуют запрещённых условием
средств (эмуляция ввода, второй аккаунт), либо не подтверждены для актуального клиента.

Поэтому требования WK-179 к Lua-аддону (режимы «основной игровой чат», «отдельное окно WoW»,
GM-стилизация внутри UI игры, `/prereborn`, установка в `Interface/AddOns`) в текущем виде
**невыполнимы** без нарушения ограничений задачи.

## Предлагаемая переработка: Twitch Chat Overlay в Companion

Отдельное окно Companion поверх игры. Это **не** внутриигровой аддон и не выдаётся за него.

- Прозрачное окно без рамки, всегда поверх; игра в режиме «Оконный (без рамки)».
  В эксклюзивном полноэкранном режиме окно поверх игры не отображается — это ограничение ОС.
- Перемещение и изменение размера; положение и размер сохраняются между запусками.
- Режим пропуска кликов: окно не перехватывает мышь, игра получает все клики.
- Twitch-чат из существующего подключения Companion — без второго подключения и без игрового
  аккаунта.
- Цветные ники (тёмные цвета осветляются для читаемости), значки стримера/модератора/VIP/подписчика.
- Эмоции 7TV, BTTV, FFZ (глобальные и канала); при ошибке загрузки показывается код эмоции.
- Два оформления: обычное (как в Twitch) и в стиле WoW-чата — строка `[Twitch] [Ник]: текст`
  с обводкой текста. Без арта и шрифтов Blizzard, без имитации GM/системных сообщений.
- Никакого взаимодействия с процессом игры: нет эмуляции ввода, чтения памяти, изменения файлов.

## Что сделано в прототипе (ветка `feat/179`)

- `src-tauri/src/chat_overlay.rs` — окно `chat-overlay` (прозрачное, без рамки, поверх всех,
  без панели задач, не забирает фокус при показе), команды показать/скрыть/пропуск кликов.
  Геометрию сохраняет уже подключённый `tauri-plugin-window-state`.
- `src/chat-overlay/` — рендер окна, загрузка каталогов эмоций с кэшем на 6 ч, мост из основного
  окна (сообщения пересылаются из существующего опроса чата раз в 1,5 с), панель управления на
  экране «Twitch-чат».
- Unit-тесты модели: фильтр команд и дублей, лимит сообщений, токенизация эмоций с сохранением
  текста и кириллицы, приоритет 7TV > BTTV > FFZ, устойчивость к падению провайдера.

## Ограничения прототипа и что нужно для полной версии

1. **Twitch-эмоции (родные и подписочные).** API сейчас не передаёт EventSub `fragments`.
   Overlay уже их понимает (поле опционально), но нужно изменение `apps/api`
   (`twitch-eventsub-chat.ts`) с деплоем через `main`.
2. **Модерация.** API не пробрасывает `channel.chat.message_delete` и `channel.chat.clear`, поэтому
   удалённые сообщения остаются в overlay. Нужны новые подписки EventSub и поле удаления в ответе.
   Состояния slow/sub-only/emote-only (`channel.chat_settings.update`) — тоже на стороне API.
3. **Значки** показываются буквенными метками, а не картинками Twitch (нужен Helix
   `chat/badges` через API).
4. **Выключение пропуска кликов** — только из окна Companion (экран «Twitch-чат»).
   Глобальная горячая клавиша — кандидат для полной версии.
5. **macOS** — окно непрозрачное (нужен `macos-private-api`); целевая платформа — Windows.
6. Не проверено на реальном WoW Forever: отображение поверх игры в режиме без рамки, отсутствие
   кражи фокуса, влияние на FPS.

## Что проверить для подтверждения архитектуры

На Windows со сборкой из PR:

1. WoW Forever в режиме «Оконный (без рамки)», Companion → «Twitch-чат» → «Показать оверлей».
2. Окно видно поверх игры, игра не теряет фокус, перетаскивание и изменение размера работают.
3. Включить «Пропускать клики» — клики по области окна попадают в игру.
4. Сообщения из чата появляются в течение ~2 с, ники цветные, эмоции 7TV/BTTV/FFZ — картинками.
5. Переключение «В стиле WoW-чата» ↔ «Обычный», прозрачность, размер текста — применяются сразу.
6. Перезапуск Companion — положение и размер окна сохранились.
7. Субъективно: нет заметного падения FPS при активном чате.
