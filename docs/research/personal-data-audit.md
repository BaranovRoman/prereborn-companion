## Question

Какие персональные данные (ПДн) фактически обрабатывают сайт prereborn.ru, API, Companion,
плагины и Twitch-расширение; на каком основании, где хранятся, кому передаются и сколько живут.
Что нужно для публичной политики (`/privacy`), регистрации и уведомления Роскомнадзора, и какие
риски остаются.

Это аудит по коду репозитория и конфигурации деплоя, а не юридическое заключение. Вывод
«проект соответствует 152-ФЗ» из него не следует. Сервер, БД и логи production не
просматривались, реальные данные пользователей не выгружались.

## Current state

- Оператор — физическое лицо (владелец проекта), юрлица нет. Хостинг FirstVDS, ДЦ IXcellerate
  (Москва) — со слов владельца; из репозитория видно только IP сервера в
  [nginx.production.conf](../../nginx.production.conf), площадку по коду подтвердить нельзя.
- До WK-191 на сайте не было политики, при регистрации не было никакого информирования,
  удаления аккаунта нет ни в UI, ни в API, ни в админке.
- Почтовых сервисов нет: подтверждение email и рассылки не реализованы.

### 2. Регистрация

1. **Запрашивается:** email и пароль (≥ 8 символов). Больше ничего.
2. **Уходит на сервер:** `{ email, password }`, `POST /api/stream/auth/register`
   (`controllers/stream/auth.ts`). Email приводится к нижнему регистру; ответ — пользователь +
   access/refresh.
3. **Основание:** обработка email/пароля необходима, чтобы предоставить сервис — естественное
   основание это п. 5 ч. 1 ст. 6 (исполнение договора). **Пользовательского соглашения (оферты)
   у проекта нет**, поэтому опереться на этот пункт пока не на что (см. «Критично»).
4. **Информирование и согласие.** С 01.09.2025 (156-ФЗ) согласие на обработку оформляется
   отдельным документом, не внутри договора или другого текста. Чекбокс «Согласен на всё»
   этим требованиям не соответствует. Если основание — договор, отдельное согласие для учётной
   записи не нужно, достаточно информирования и доступной политики. В рамках WK-191 добавлено
   информирование и ссылка на политику; согласие не добавлялось.
5. **Подтверждения email нет**, CAPTCHA нет. Есть ограничение частоты на register/login
   (`streamAuthRateLimiter`). Ответ `409 «Этот email уже занят»` позволяет перебором проверить,
   зарегистрирован ли email.
6. **Получить сведения о своих данных** можно только запросом оператору; экспорта нет.
   Личный кабинет показывает email, привязки и статус Companion.
7. **Удаление аккаунта:** ни в UI, ни в API, ни в /admin его нет. Сейчас удалить можно только
   вручную SQL-запросом `DELETE FROM stream_users WHERE id = …` (каскад удалит всё связанное),
   плюс вручную удалить файлы из `uploads/`.
8. **После удаления:** каскадом удаляются токены, привязки Twitch/DA/Steam, матчи, сессии,
   викторины, донаты и активность. Не удаляются файлы в `uploads/`. Токены Twitch/DA на стороне
   провайдеров не отзываются (`revoke` не вызывается — **при отключении интеграции тоже**).
   Живой EventSub-сокет в памяти закрывается только при отключении Twitch.
9. **Остаётся после удаления:** строки в nginx/PM2-логах до их ротации; резервные копии, если они
   есть (в репозитории бэкапов нет — уточнить у владельца/FirstVDS).
10. **Использование не по назначению:** не найдено. Email используется только для входа и
    проверки admin-allowlist, писем нет.

| Email-сервисы, аналитика, внешние скрипты | — | — | — | — | Не найдены |

**Трансграничная передача.** Единственный кандидат на передачу ПДн, которые хранит оператор,
за рубеж — Dota account id в OpenDota и ник PUBG в KRAFTON. Это идентификаторы, связанные
у нас с учётной записью и отправляемые по инициативе пользователя. Нужно ли по ним уведомление
по ст. 12, решает юрист. Запросы к Twitch с токеном пользователя и обращения браузера к CDN
к передаче ПДн оператором не относятся. Это наша оценка, она требует проверки.

**Локализация (ч. 5 ст. 18 в ред. 23-ФЗ, с 01.07.2025).** Первичная запись email, паролей и
привязок идёт в PostgreSQL на сервере в РФ, внешние сервисы не служат первичной БД. Подтвердить
физическое расположение БД и бэкапов может только владелец (договор/панель FirstVDS).

### 4. Инфраструктура и безопасность

| Пункт | Состояние | Источник |
|---|---|---|
| Основная БД | PostgreSQL на том же сервере, `pg` через `DATABASE_URL` | env, deploy workflow |
| Бэкапы | **не найдены в репозитории** | — |
| Логи | nginx access/error в `/var/www/httpd-logs/`, PM2 stdout | `nginx.production.conf`, `ecosystem.config.cjs` |
| TLS | HTTPS + редирект 80→443, HSTS в API (helmet, prod). **Включены TLSv1 и TLSv1.1** | `nginx.production.conf` |
| Секреты | GitHub Secrets → `.env` при деплое | `deploy-production.yml` |
| OAuth-токены Twitch/DA | открытым текстом в БД | `migrate.ts` |
| Admin API | `authenticateStreamUser` + email allowlist | `require-admin.ts` |
| Загрузки | публичные по случайному URL, `Cache-Control: public, immutable, 30d` | nginx |
| Токены сайта | `localStorage` | `tokens.ts` |
| Удаление данных | только каскад при ручном `DELETE` | — |
| Избыточность | `stream_users.public_token` хранится открыто (нужен для URL оверлея — оправдано); GSI payload целиком (может содержать имя игрока в Steam) — допустимо, одна строка | — |

**localStorage против HttpOnly cookie.** Любой XSS на prereborn.ru может прочитать refresh-токен
(30 дней, с ротацией) и получить доступ к аккаунту, включая выпуск токена Companion и доступ к
Twitch-клипам от имени канала. Компенсирующие меры сейчас: React-экранирование,
`sanitize-html` на сервере, отсутствие сторонних скриптов. Если перенести refresh в
`HttpOnly; Secure; SameSite=Strict` cookie на `/api/stream/auth`, а access оставить в памяти,
XSS не сможет украсть долгоживущий токен. Но придётся менять API (cookie-путь для
refresh/logout, CSRF-защита для этих двух эндпоинтов) и клиента. Companion этим не затронут:
он передаёт refresh в теле. Это миграция авторизации, и по условиям тикета **в WK-191 она не
делается**. Предлагается отдельный тикет.

## Options

Основание обработки данных аккаунта:

1. **Договор (оферта) + политика, без отдельного согласия.** Основание естественное: без email
   сервиса нет. Регистрация не усложняется, требования 156-ФЗ к согласию не применяются. Нужен
   текст соглашения. **Рекомендуется.**
2. **Отдельное согласие по ч. 4 ст. 9.** Требует ФИО и адреса оператора в тексте согласия,
   отдельного документа и отдельного действия при регистрации, а отзыв согласия фактически
   означает удаление аккаунта. Регистрация сложнее, выгоды нет.

## Recommendation

- Влить WK-191 (черновик политики, информирование, ссылки). На production страница уходит с
  баннером «Черновик» и `noindex`, пока не заполнены реквизиты в
  `apps/web/src/shared/config/legal.ts` — сайт не публикует неподтверждённых сведений.
- Владелец предоставляет реквизиты (список ниже), юрист проверяет формулировки, затем заполняется
  конфиг и снимается черновик (и тест `keeps the shipped config a draft…` переворачивается).
- Отдельными тикетами: C2, C3+I4, C5, I1+I2+I6, I3, I7, U1.

### Что нужно от владельца

1. ФИО оператора (как в паспорте).
2. Адрес для письменных запросов субъектов: публиковать ли его на сайте или ограничиться
   email (решение владельца/юриста; в уведомление РКН адрес нужен в любом случае).
3. Email для обращений по ПДн.
4. Дата вступления политики в силу.
5. Срок хранения nginx-логов (или согласие настроить logrotate на N дней).
6. Есть ли бэкапы БД (FirstVDS или свои), где они хранятся и сколько.
7. Подтверждение площадки (FirstVDS, ДЦ IXcellerate, Москва) — для уведомления РКН.
8. Подавалось ли ранее уведомление в РКН.
9. Решение по основанию: пользовательское соглашение (рекомендуется) или отдельное согласие.

### Формулировки, требующие юридической проверки

- Раздел 4 политики: п. 5 ч. 1 ст. 6 без принятого соглашения; п. 7 ч. 1 ст. 6 для зрителей и
  донатеров.
- Раздел 7: квалификация передачи id в OpenDota и ника в PUBG API.
- Раздел 9: срок ответа 10 + 5 рабочих дней (ст. 14, 20 в ред. 266-ФЗ).
